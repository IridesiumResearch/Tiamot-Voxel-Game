# TASK 14 — Moddable UI: declarative server dialogs + client-side HUD API

Depends on: 13. Schema types in `crates/core::ui`; renderer in `crates/client`.

## Objective
Two tiers matching the trust model: untrusted server mods describe UI as data (no code
crosses the wire); trusted client-side scripts get an immediate-mode HUD API. Replace the
placeholder egui hotbar/inventory with this system eating its own dogfood.

## Design
### Tier 1 — Declarative dialogs (server → client, data only)
- Widget tree as Lua tables → serialized schema (postcard). Layout model: flex-style
  containers (row/column, grow/shrink, gap, padding, align), NOT absolute coordinates.
  Widgets v1: container, label, button, image (content-hash ref), text_input, checkbox,
  slider, dropdown, item_slot / item_grid (binds to inventory views), scroll, spacer,
  progress. Styling: limited token set (background, border, nine-slice image, text
  color/size) — deliberately constrained; resist adding a CSS.
- API: `game.show_dialog(player, tree, formname)`, `game.update_dialog`, `game.close_dialog`;
  interactions return to the OWNING SERVER MOD as `on_dialog_event(player, formname, event)`
  (button presses, input submissions, slot clicks). Server validates everything (slot moves
  are requests, inventory stays authoritative). Rate limits + max tree size/depth enforced
  at decode.
- Client renders the schema natively (build on egui internally but do NOT expose egui types
  in the schema — the schema is the stable contract; egui is swappable).
- Item slots: define inventory views (`player:main`, `player:hotbar`, mod-defined containers)
  with server-checked move/split semantics (click, shift-click, drag patterns like Minecraft;
  right-click splits stacks on the 27-unit arithmetic — splitting 40 units gives 20/20,
  display handles blocks+spares).
### Tier 2 — Client-side HUD API (trusted-sandboxed scripts)
- Per-frame immediate API for pushed client scripts: `hud.text/rect/image/bar/icon(...)` in a
  virtual-resolution coordinate space with anchor points; `hud.hide_builtin(element)` to
  replace engine defaults. Read-only game state access: own position/health/inventory/target,
  time of day. Strict per-frame instruction budget (Task 05 machinery).
### Dogfood in `game/`
- `game/core_ui/`: rebuild hotbar + crosshair + dig-progress + health as Tier-2 HUD;
  player inventory screen (item_grid + crafting-free layout for now) as a Tier-1 dialog;
  a pause/settings entry that opens ENGINE settings (settings/rebinding stay engine-native —
  they must work with zero mods loaded).
- Chat: engine-native line input + history overlay; `game.register_on_chat(fn(player, msg))`
  with cancel; server echo with basic formatting codes. (Chat is engine because moderation
  and RCON depend on it.)

## Tests
- Schema: serialize/deserialize round-trip proptest; depth/size limit rejection; add
  `fuzz/dialog_schema` for the client-side schema decoder in THIS task (charter rule 14 —
  server-sent trees are hostile input), wired into the CI fuzz smoke job; unknown
  widget tag = clean error to the mod, not a client crash (forward-compat rule: client
  ignores unknown OPTIONAL fields, rejects unknown widget types with an error event).
- Layout engine unit tests: table-driven flex cases with expected rects (headless).
- Inventory-move authority: hostile bot sends forged slot-move events → server rejects,
  state unchanged (extend bot with raw-message injection for this).
- Integration: bot opens the inventory dialog, moves a 40-unit stack, splits it, asserts
  server inventory; dialog update round-trip latency logged.
- HUD budget: a pushed script exceeding the frame budget is throttled with a user-visible
  mod-attributed warning, engine HUD unaffected.
- Screenshot smoke goldens for the dialog renderer (fixed tree → hash).

## Acceptance criteria
- [A] Default hotbar/inventory fully replaced by `game/core_ui` (delete the mod ⇒ minimal
      engine HUD only: crosshair + chat + settings — verify).
- [A] A server mod can show an interactive dialog to a vanilla client with no code push.
- [A] Forged-event and oversized-tree attacks handled per tests.
- [A] Splitting/merging stacks in UI respects 27-unit display everywhere.
